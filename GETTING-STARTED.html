What is MonitorIT?

MonitorIT is a dashboard you keep open during a maintenance window. It pings a list of hosts continuously, like PingInfoView, and traces the route to up to two of them every second, like WinMTR, all on one screen. It tells you when something went down, for how long, and whether traffic took a different path.

The problem it solves. During a change window you usually juggle several tools: a ping monitor for "is everything still up?", a WinMTR window or two for "did the route fail over?", and notes for "when did it drop and for how long?". It's easy to miss a short outage or a failover while you're typing on a switch. MonitorIT puts all of that in one place. It marks route changes with a banner and a beep, and writes every outage, recovery and route change, with a timestamp, to a log file you can open in Excel afterwards.

What it does

  • Pings every host in your list every 3, 5 or 10 seconds and shows its status, response time, packet loss, when it was last seen, how many outages it had and the total downtime.
  • Traces the route to up to two hosts every second, with loss and response time per hop.
  • Locks a baseline route before the change and warns you, with a banner and an optional beep, as soon as the path differs from it.
  • Logs every event with a timestamp (host down, host up with the outage length, route changed, route back on baseline) to a daily CSV file that opens in Excel.
  • Saves host lists as profiles, so you can reload your list for the next window.

MonitorIT only sends pings and traceroute probes. It never logs into or changes any device. It needs no installation and no admin rights.

Getting started

  1. Extract the zip to a folder you own, e.g. Documents\MonitorIT: right-click the zip → Extract All…. Don't run it from inside the zip.
  2. Double-click LaunchIT.bat. A black console window opens, then your browser opens the dashboard at http://127.0.0.1:8000. Keep the console window open while you use MonitorIT; closing it stops the app.
  3. MonitorIT starts with the sample profile (localhost and a few public DNS servers). The public ones may show Offline if your network blocks ping to the internet. That's expected.
  4. Add your own hosts: click + Add / Import Hosts (see Adding hosts). Untick Append to replace the sample hosts instead of adding to them.
  5. Save your list: click Save As… and give it a name. Next time, pick it from the Profile list at the top and click Load.
The first time you run it, Windows may show "Windows protected your PC" because LaunchIT.bat came from a zip. Click More info → Run anyway. If your laptop doesn't allow that, right-click the zip → Properties → tick Unblock → OK, then extract it again.

Watching hosts

StatusMeaning
PENDINGNot pinged yet.
ONLINEThe last ping was answered.
TIMEOUTMissed a ping, but not enough in a row to count as down yet.
OFFLINEMissed the Down After number of pings in a row. An outage is logged.
  • Down After (toolbar) sets how many failed pings in a row mark a host down. The default is 2, so a single dropped ping doesn't raise an alarm. Use 1 for the fastest detection, or 3–5 on lossy links.
  • Outages and Downtime count only for hosts that were up before. A host that has never answered shows Never under Last Seen.
  • Hover over RTT, Avg, Outages or Downtime for more detail (min/avg/max, longest outage, when the current outage began).
  • Click a Friendly Name to rename a host. Click ✕ to remove one from the list.
  • Type in Filter hosts to find a host in a long list.

Watching a route

  1. Click Monitor Route next to a host. Its traceroute appears in slot 1 (a second host goes in slot 2).
  2. Before the change, once all hops have answered, click Lock Base. The current route becomes the baseline, shown in the Baseline column.
  3. If the route then differs from the baseline, the slot shows PATH CHANGE DETECTED, the hops that moved are highlighted, and the event log records it. When the route returns to the baseline, that's logged too.
  4. Turn Audio on (top right) to hear a beep on every route change, even when you're looking at another window.
  5. Reset Stats restarts that slot's loss counters, e.g. at the start of the window. The baseline is kept. Stop ends the traceroute.

Reading hop loss

Routers answer traceroute probes at low priority and often limit how many replies they send, so a hop can show loss while traffic through it is fine. MonitorIT works out which case it is:

Loss shown asMeaning
Amber, boldThe loss continues through every later hop to the destination: probably real packet loss.
GreyLoss at this hop only, not at later hops: the router is limiting its replies. Not a problem.
NormalNo loss, or the destination hasn't answered yet, so it can't be judged.

A hop shown as * didn't answer that probe. A hop that never answers is a router set not to reply to traceroute; traffic still passes through it. Missing answers are never reported as route changes. Hover over a hop for its full statistics.

The event log

  • The strip under the host table lists every event, newest first: Critical (host down, route off baseline), Warning (route changed), Success (host back up, with how long it was down; route back on baseline) and Info.
  • Use the filter to show Alerts only, Hosts or Routes. Click the header to fold the strip away; a red counter then shows new alerts.
  • Every event is also saved to logs\MonitorIT_events_YYYY-MM-DD.csv in the MonitorIT folder, one file per day. It opens in Excel, ready for the change report.
Opening a log file in Excel while MonitorIT is running locks it, so new events can't be written. They're kept in memory and saved once you close Excel, and the strip shows a warning until then. To look at a log during the window, open a copy of the file, or use Export CSV.

Lines that can't be used (a name that doesn't resolve, a duplicate, an IPv6 address, a subnet larger than /22) are listed back to you with the reason. Only IPv4 is supported.

Keeping things safe

  • MonitorIT only listens on your own laptop (127.0.0.1); nobody else on the network can reach the dashboard.
  • Your profiles and logs contain internal IP addresses and device names. They stay in the profiles and logs folders on your laptop. Don't post them anywhere public.
  • If you pass MonitorIT on, share the original zip, not your own MonitorIT folder (it holds your profiles and logs).
  • Log files are never deleted automatically. Delete old ones from logs when you no longer need them.

Updating to a new version

  1. Close MonitorIT (close its console window).
  2. Extract the new zip to a new folder.
  3. Copy your own profiles (the .json files in profiles) and, if you want to keep them, the logs folder from the old folder into the new one.
  4. Run the new LaunchIT.bat. Once it works, delete the old folder.

If something goes wrong

What you seeWhat to do
The console window flashes and closes, or shows an errorMake sure you extracted the whole zip and are running LaunchIT.bat from the extracted folder. Send a screenshot of the console to whoever gave you MonitorIT.
The browser doesn't openOpen http://127.0.0.1:8000 yourself while the console window is open.
An error in the console saying "only one usage of each socket address" (error 10048)Something is already using port 8000, often MonitorIT itself in another console window. Use that one, or close it first. If it's another program, open LaunchIT.bat in Notepad, change set "PORT=8000" to e.g. 8080, and use that number in the address.
WS Status (top right) says DisconnectedThe console window was closed or the app stopped. Start LaunchIT.bat again; the page reconnects by itself.
Every host shows OfflineCheck the VPN or network connection. Ping (ICMP) may be blocked between your laptop and those hosts; try one with the Windows ping command.
A route keeps changing back and forthSome paths share traffic across several links (load balancing), so different routers answer at the same hop on successive traces. Each switch is reported as a change; judge it with the hop list.
"⚠ … event(s) not yet saved to disk" in the event logA log file is open in Excel. Close it; the events are written straight away.
